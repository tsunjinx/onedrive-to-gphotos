## Findings and resolutions

1. **Required: account binding was underspecified.** Add explicit identity scopes and a trusted identity verification mechanism. Persist stable account/client identifiers and refuse resume under a different account or app. This is part of the authentication slice, not implemented yet.

3. **Required: video upload is not video completion.** Retain the distinct processing state and app-created read permission. Pending videos must remain resumable without another upload; processing failure must be visible.
4. **Required: large-file staging could deadlock under too-small limits.** Retain preview checks for largest-file capacity, encryption overhead and free space. Never wait indefinitely for a file that cannot fit the configured budget.
5. **Required: success claims must match evidence.** Local configuration validation does not prove login; API creation does not prove video readiness; cross-builds do not prove native runtime behavior. Tasks stay unchecked until their acceptance checks actually run.
6. **Simplification: no CLI framework is needed yet.** Start with standard-library command handling and no external dependencies. Keep reviewed OAuth/keyring dependencies for the security-sensitive authentication slice rather than implementing cryptographic protocols from scratch.
7. **Scope: no storage-size interview blocks coding.** Discovery can calculate size later. Account registration, local toolchain and live consent are the actual first-milestone prerequisites.
