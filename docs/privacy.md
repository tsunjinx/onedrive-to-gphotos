# od2gp privacy notice

Current implementation: authentication, source inventory and user-started media transfers. You select and authorize your own OneDrive source and Google Photos destination. The app requests read-only OneDrive access, Google Photos upload/app-created read access and basic identity/offline access needed to maintain that connection. Signing in does not start a media transfer.

Passwords are entered only in the provider's browser flow. Google and native Microsoft login store compact refresh credentials and account identity in macOS Keychain or Windows Credential Manager. Native Microsoft credentials also retain the selected drive ID. Existing rclone jobs use their dedicated encrypted config file for OAuth tokens; its encryption key remains in the OS credential store. Source inventory counts metadata in memory and prints totals. Drive inspection temporarily reads metadata and displays folder names and sample photo/video paths in the terminal; it downloads/uploads no media and creates no persistent preview cache. Access tokens are held in memory. No hosted relay, analytics, advertising, data sale or model training is used. Microsoft and Google receive the API requests required for authorization and identity checks.

Saved credentials remain until you run `auth logout onedrive` or `auth logout google`. These commands remove local credentials and leave cloud media untouched. Remote grants can be revoked at [Microsoft consent management](https://account.live.com/consent/Manage) or [Google connections](https://myaccount.google.com/connections). A downloaded Google OAuth client JSON file remains at the path you supplied; delete it manually when no longer needed. Rclone logout removes its remote but retains the encrypted config key for future reconnects. Migration records and session credentials are encrypted in a persistent local SQLite database, keyed by an OS credential-store key. Media bytes are staged locally in authenticated encrypted chunks and removed after destination creation is durably recorded. Download and upload chunks exist temporarily in process memory. Reports explicitly requested by the user contain filenames/state and destination IDs; they do not contain upload tokens. Journal records are retained to support resume and auditing. Legacy rclone first-run downloads contact downloads.rclone.org for the executable and checksum manifest; native Graph jobs do not launch or install rclone.

A transfer copies selected photos and videos from OneDrive through an encrypted local cache to Google Photos, retaining source originals. Live media transfer verification is still pending. To delete local migration data after completion, first ensure no job is running, then remove only the selected job directory under od2gp/jobs/JOB_ID and its matching migration-JOB_ID credential-store key. This loses resume/history for that job and does not delete cloud media.

The use of information received from Google APIs will adhere to the [Google API Services User Data Policy](https://developers.google.com/terms/api-services-user-data-policy), including Limited Use requirements. This is an independent personal project and is not endorsed by Microsoft or Google.

With the legacy rclone backend, opt-in `source scan --diagnostics` displays up to 16 KiB of source failure details in the terminal, which may contain folder/file names and provider account details. URLs and recognized credential fields are redacted, but review diagnostic text before sharing it. These details are held in memory, not written to a diagnostic file. Normal errors retain fixed sanitized categories.
